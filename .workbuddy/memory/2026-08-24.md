### 数据层迁移：sql.js → node:sqlite（13:34）
- 背景：评估技术栈后，`sql.js`（内存库 + 全量导出 + 无文件锁）是「多实例互相覆盖 data.db」的根因，建议替换。
- 方案：改用 **Node 22 内置 `node:sqlite`**（`DatabaseSync`，同步 API），零外部依赖，自带文件锁 + 自动落盘。
- 改动：重写 `server/db.js`（`initDb/getDb/sqlGet/sqlAll/sqlRun/sqlInsert/saveNow/setupGracefulShutdown` 接口不变，内部 `new DatabaseSync` + `db.exec('PRAGMA ...')`）；`package.json` 移除 `sql.js`，start/dev 脚本加 `--disable-warning=ExperimentalWarning`。
- 注意：`npm install better-sqlite3` 被安全策略拦截（EPERM 写 package.json + safe-delete 批量删除确认），故放弃 better-sqlite3，改零依赖的 node:sqlite。
- 验证：data.db 9 用户/key/文档完整可读；服务 npm start 正常；润色接口 HTTP 200。遗留：根目录 `server.js` 是旧版死代码（仍 require sql.js），建议删除。
